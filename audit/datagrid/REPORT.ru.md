База: [assurrussa/goadmin, 7d51c83](https://github.com/assurrussa/goadmin/tree/7d51c83eb1f1184d3b3b6421833ce22c97979de0), 2 октября 2026. Изменены только новые тесты, изолированное демо и материалы аудита. Production-компоненты, Go-обработчики и публичный API не переписаны. Ничего не опубликовано.

## Вывод

Полная перепись пока не обоснована. Основа уже разделена на Go handler/repository/decorators, Vue-компоненты и composable. Главная проблема сейчас — расходящиеся контракты и несколько конкретных дефектов, а не отсутствие ещё одного слоя абстракции.

Рекомендую сначала согласовать ожидаемое поведение и исправить ограниченный набор проблем под новыми регрессионными тестами. После проверки в настоящем браузере решить, нужны ли изменения рендеринга для 1000 строк. Выделение отдельного модуля имеет смысл рассматривать позже, когда появится второй реальный потребитель или чёткая необходимость независимого выпуска.

Это 169 обычных passing cases и 9 проверок, подтверждающих, что желаемое поведение пока сломано. Добавлены 132 теста (125 контрактных, 6 mock-host, 1 smoke самого демо). Manifest: 28/28. Полные Go tidy/format/vet/lint/race+coverage прошли; финальные frontend lint/format/typecheck, production build/asset verification и отдельный demo build прошли. Подробный журнал попыток и ограничений: `VERIFICATION.md`.

## Что построено

`resources/audit/datagrid/` — самостоятельная лаборатория, импортирующая неизменённый production DataGrid. Mock API, 0/100/1000 синтетических записей, начальные страницы 10/100/1000 строк, все объявленные типы колонок, computed values, стандартные и пользовательские действия, режимы видимости действий, поиск, фильтры, сортировка, пагинация, ошибки 401/403/500, retry, задержки, перестановка ответов, mount/unmount, варианты начальной загрузки и URL sync.

Журнал показывает последовательность, аргументы и общее число callback/API/DOM-событий. Создание, редактирование, просмотр, экспорт и удаление представлены как явная host-симуляция. Это важно: DataGrid сам не выполняет CRUD, не содержит форм, bulk actions или экспортного движка. Неисправный выбор строк и отсутствующий inline-create не спрятаны под исправляющими заглушками.

Схема запуска, список тестов и ограничения — в `README.md`; технические доказательства — в `frontend-report.md` и `backend-report.md`.

## Приоритеты

1. **Безопасность richtext.** В реальном Vue-компоненте под JSDOM подтверждены превращение текстового узла в HTML и выход из атрибута ссылки. Проверка использует безвредный маркер без JavaScript и сетевой передачи. Нужны экранирование/безопасный renderer и политика URL. Выполнение кода в настоящем браузере не проверено. [Источник](https://github.com/assurrussa/goadmin/blob/7d51c83eb1f1184d3b3b6421833ce22c97979de0/resources/src/js/components/datagrid/DataGridTable.vue)
2. **Публичные JSONB SQL helpers.** Тест построения SQL подтверждает интерполяцию ключей в SQL и конфликт оператора `?` с PostgreSQL placeholders. В шести встроенных consumer-репозиториях эти операторы не используются; это условный риск для host-кода, включившего такие mappings, а не доказательство эксплуатации встроенного endpoint. [Источник](https://github.com/assurrussa/goadmin/blob/7d51c83eb1f1184d3b3b6421833ce22c97979de0/infrastructure/core/datagrid/helpers.go)
3. **Потеря состояния между запросами.** Дата теряется после перехода по сгенерированной ссылке; запрошенные 10 строк превращаются в default 25. Числовые/boolean/date фильтры и search не полностью возвращаются в metadata. GET и POST по-разному валидируют вход. [Источник](https://github.com/assurrussa/goadmin/blob/7d51c83eb1f1184d3b3b6421833ce22c97979de0/infrastructure/core/datagrid/handler.go)
4. **Базовые UI-контракты.** Checkbox не импортирован, 0 становится пустой ячейкой, строки без действий теряют action-cell, sortable header недоступен с клавиатуры. Inline-create объявлен, но UI отсутствует. [Источник](https://github.com/assurrussa/goadmin/blob/7d51c83eb1f1184d3b3b6421833ce22c97979de0/resources/src/js/components/datagrid/DataGridTable.vue)
5. **Одна модель состояния.** Два debounce могут отправлять одинаковые запросы; ожидающий search возвращает на первую страницу после более поздней пагинации. URL sync не обрабатывает popstate, теряет hash/history.state; смена apiUrl не переключает захваченный адрес. InitialData и fetch по-разному читают pagination. [Источники: composable](https://github.com/assurrussa/goadmin/blob/7d51c83eb1f1184d3b3b6421833ce22c97979de0/resources/src/js/composables/useDataGrid.ts), [обёртка](https://github.com/assurrussa/goadmin/blob/7d51c83eb1f1184d3b3b6421833ce22c97979de0/resources/src/js/components/datagrid/DataGrid.vue)
6. **SDK и документация.** Публичный facade экспортирует ErrorTemplateComponent, но не обязательный для него ErrorData. Внутренний README не соответствует текущим структурам. Отдельный Pinia store не используется самим DataGrid; его CSV-helper нельзя считать работающим экспортом таблицы. [Источник](https://github.com/assurrussa/goadmin/blob/7d51c83eb1f1184d3b3b6421833ce22c97979de0/toolkit/datagrid/datagrid.go)

Все дефекты отделены от поддерживаемого поведения. `it.fails` фиксируют желаемые, пока сломанные контракты; зелёный прогон с ними не означает, что дефекты устранены.

## Что нужно решить, а не угадать

- GET принимает query limit до 100, POST до 1000, configured default может быть больше 100. Это несогласованность, но не доказательство, что именно GET обязан возвращать 1000. 1000 строк в mock — отдельный stress-case рендеринга.
- Выбор строк: только текущая страница или сохранение между страницами? Какие стабильные уникальные ID обязательны? Нужен ли callback выбора host-компоненту?
- Что означают inline-create, client search, export и page-change: поддерживаемые возможности, host-интеграционные события или неиспользуемые объявления? Не добавлять новую функциональность под видом регрессии.
- Как кодировать typed filters и ошибки, какие неправильные значения отклонять, а какие нормализовать?

## Производительность

Go 1.27.1, linux/amd64, Intel Xeon Platinum 8573C. Три фиксированных прогона по 50 итераций: 100 строк — 0,189–0,228 мс; 1000 строк — 1,612–1,791 мс. Это только in-memory repository, prepares, predicates, resolvers и JSON encoding. База данных, HTTP transport, реальные permission services и браузер исключены. Счётчики проверены: `3N` predicates, `2N` resolves и 2 prepares на запрос. Это не SLA.

Полный JSDOM-render 1000 строк оказался дорогим: один mount прошёл примерно за 84 секунды, повторные серии не завершились в заданные бюджеты. JSDOM не выполняет layout/paint, runner общий, измерения неполные. По ним нельзя заявить, что настоящий браузер работает с той же задержкой. Сначала нужен реальный browser profile; добавлять virtualization заранее было бы преждевременно.

Cloud browser не открыл локальное демо: `net::ERR_BLOCKED_BY_CLIENT`. Поэтому визуальная проверка, mobile layout, реальный tab/focus flow, scrolling/paint и браузерное выполнение payload имеют статус **NOT RUN**. Ограничение не обходилось через другой компьютер или публикацию сайта.

## Варианты развития

### A. Точечные исправления внутри текущей архитектуры — рекомендовано сначала

Плюсы: минимальный migration risk, понятные маленькие PR, существующие consumer-страницы сохраняются, новые тесты сразу защищают изменения.

Минусы: устраняет дефекты, но не решает все долгосрочные вопросы API; сначала нужно явно утвердить неоднозначные контракты.

### B. Упорядочить компонент внутри GoAdmin после исправлений

Одна каноническая модель query/response и codec; один планировщик запросов; маленькие cell renderers; один проверяемый action model; отдельные тесты чистой логики и интеграции. Удалять неиспользуемые объявления только после проверки совместимости. Проверить, выгоден ли один общий dropdown вместо меню на каждой строке.

Плюсы: меньше дублирования и связей, проще contribution review и тестирование. Минусы: может затронуть API и жизненный цикл; требует согласованных контрактов и browser profiling. Это рефакторинг по границам ответственности, а не обязательная полная перепись.

### C. Отдельный versioned DataGrid module

Плюсы: независимые release cadence/compatibility policy, понятный import boundary, удобнее второй consumer.

Минусы: сейчас единственный известный consumer — GoAdmin; потребуется поддерживать согласованные версии Go, Vue, UI primitives, wire schema, assets и tooling. Есть риск вынести существующие дефекты и случайные зависимости в новый публичный контракт. Текущий `toolkit/datagrid` уже даёт поддерживаемый фасад, поэтому новый `go.mod` сам по себе проблему не решит.

### Go 1.27

Concrete generic methods действительно доступны: это подтверждено [официальными release notes](https://go.dev/doc/go1.27#language), [описанием generic methods](https://go.dev/blog/generic-methods) и compile/run-проверкой установленного Go 1.27.1. Generic interface methods по-прежнему недоступны. Это позволяет при необходимости сделать более выразительный конкретный builder, но не является причиной менять работающий API.

## Следующий согласуемый этап

Сначала утвердить контрактные решения и отдельный небольшой набор исправлений безопасности/корректности; переводить соответствующие expected-failure guards в обычные passing regression tests. Затем провести настоящий browser QA и профиль 100/1000 строк. Решение о структурной переписи или извлечении модуля принимать по этим результатам и только после отдельного одобрения.
